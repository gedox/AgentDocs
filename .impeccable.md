# Design Context — AgentDocs

**Target audience:** A single technical user (the tool's owner) — a developer who
scrapes documentation and feeds it to AI coding agents. Runs locally on their own
machine.

**Use cases:** Browse folders of scraped Markdown docs; turn a doc set into an
AI-buildable "blueprint" via a local Ollama model; preview generated files; copy
project commands; run commands in a built-in mini-terminal.

**Brand personality / tone:** An architect's drafting table. Precise, utilitarian,
confident. Paper-and-ink, not neon-on-black. The "blueprint" metaphor is literal
and runs through the whole interface — drafting grid, dimension ticks, measured
type, annotations set in monospace.

**Aesthetic direction:**
- Light "drafting paper" base (warm tinted neutral), deep ink navy text.
- Single strong accent: drafting rust/red for primary actions; muted blueprint
  blue as secondary.
- Subtle blueprint grid in the background (purposeful, reinforces concept).
- Serif for headings (editorial/drafting feel), clean sans for UI, monospace ONLY
  for terminal output and copyable commands (semantically correct there).
- Self-contained: no external fonts/CDNs (runs offline on localhost).

**Anti-slop guardrails:** no cyan-on-dark, no purple gradients, no glassmorphism,
no dark-mode-with-glow default, no Inter/Roboto, no card-grid monotony.
